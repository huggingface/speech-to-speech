# speech-to-speech v1.1.0

This release adds a native CPU text-to-speech backend, more speech, diarization
and voice-activity backends, per-session language selection, turn-latency
reporting, and YAML configuration. These notes cover changes since v1.0.0.

## Highlights

- **Phonon: local streaming speech on CPU.** Gradium's Phonon runs through the
  Rust-backed `ptts` runtime, with no PyTorch, and streams 16 kHz audio with
  interruption support:

  ```bash
  pip install "speech-to-speech[phonon]"
  speech-to-speech local --tts phonon
  ```

  The default checkpoint, `gradium/phonon-40m-en`, is gated: accept its terms on
  Hugging Face, then run `hf auth login` or set `HF_TOKEN`. Its weights are CC
  BY-NC 4.0 (non-commercial); the Apache-2.0 `gradium/phonon-31m-en` is available
  with `--phonon_tts_model_name`. Voices come from the checkpoint and the Phonon
  voice catalog. In `local`, the arrow keys switch voices between replies.
- **More speech backends.** New STT backends: Parakeet Unified, Nemotron
  streaming (including Persian), SenseVoice, and Orukeet. New TTS backends:
  KittenTTS on CPU, MiniMax, and streaming Drama-3. Pocket TTS supports its Farsi
  v2 weights, and OmniVoice accepts per-language reference voices. Also new:
  optional FireRed streaming VAD and Nemotron 3 speaker diarization for live
  conversations. Speech-to-viseme output is available again on the Realtime
  pipeline.
- **Language selection and detection.** Realtime sessions can select a speech
  language with `session.audio.input.transcription.language`, change it live, or
  return to `auto`. With `--detect_llm_output_language`, TTS follows the
  language of the assistant's reply.
- **Turn-latency reporting.** `response.done` logs and response metadata break
  each turn into VAD, Smart Turn, STT, LLM and TTS waits, with first-text and
  first-audio timings for most built-in backends. The browser demo shows
  server timings in its history.
- **Configuration and setup.** Optional YAML configuration supports configured
  startup (`speech-to-speech serve -f config.yaml`). `--torch_num_threads` sets
  PyTorch CPU threads. `local` shows a clean conversation view by default. New
  guides cover LiveKit Agents, a keyless You.com web search tool, and DGX Spark.
- **More reliable Realtime conversations.** This release honors
  `create_response: false` and preserves Responses reasoning context across tool
  continuations. It accepts client call IDs without the `call_` prefix and
  limits generated function-call IDs to 32 characters. Speculative-turn ordering
  is stricter, and microphone and output audio are resampled continuously
  across chunks. WebRTC no
  longer sends idle audio packets, and Silero VAD resets its state after each
  segment.

## Upgrading from v1.0.0

In your Python environment:

```bash
pip install --upgrade "speech-to-speech==1.1.0"
```

- **Python 3.11 or newer is required.** Python 3.10 support was removed; Python
  3.13 and 3.14 are now supported.
- **The default local LLM is now Qwen3.5-4B.** `local` and `serve` use
  `mlx-community/Qwen3.5-4B-4bit` on Apple Silicon and `Qwen/Qwen3.5-4B` with
  Transformers elsewhere. To keep the previous model, pass
  `--model_name mlx-community/Qwen3-4B-Instruct-2507-4bit` or
  `--model_name Qwen/Qwen3-4B-Instruct-2507`.
- **Kokoro on macOS needs its extra.** Its phonemizer dependencies are no longer
  part of the base macOS installation. Install
  `speech-to-speech[kokoro]` before using `--tts kokoro`.
- **`local` hides diagnostics by default.** It shows only the conversation; add
  `--verbose` for routine logs, tool details and Realtime events.
- New optional extras: `phonon`, `kitten`, `fireredvad`, `nemo`, and
  `sensevoice`. The `webrtc` extra now requires `aiortc<1.16`.

## Compatibility and setup

- Installation smoke tests cover Python 3.11–3.14 on Linux and Apple Silicon.
- Realtime compatibility covers the documented core event set, not every
  OpenAI Realtime API feature. See the
  [protocol reference](../../src/speech_to_speech/api/openai_realtime/README.md).
- Phonon runs on CPU even when other components use a GPU. Its thread count
  defaults to four; tune it with `--phonon_tts_num_threads`.

See the [README](../../README.md) for starting configurations and the
[full changelog](https://github.com/huggingface/speech-to-speech/compare/v1.0.0...v1.1.0)
for all changes and contributors.
